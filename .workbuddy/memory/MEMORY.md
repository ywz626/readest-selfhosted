# Readest 自托管分支 — 项目长期笔记

## 仓库结构（关键事实）

- 本地分支 `master` = **自托管分支**（只跟踪 `origin`，即 github.com/ywz626/readest-selfhosted）。
- 本地分支 `main` = **上游原版分支**，跟踪 `remote/main`。
- 远端：`origin` / `my_readest` 都指向 ywz626/readest-selfhosted；`remote` 指向上游 readest/readest。
- 同步上游的正确姿势：
  ```bash
  git fetch remote --tags
  git merge remote/main        # 在 master 上
  git submodule sync --recursive && git submodule update --init --recursive
  pnpm install
  ```

## 自托管改造的核心锚点（合并时务必保留）

- `apps/readest-app/src-tauri/tauri.conf.json`：`productName: "Readest 自托管"`、`mainBinaryName: "readest-sh"`、`identifier: "com.ywz626.readest.sh"`。
  `beforeBuildCommand` 必须带 `-e .env.server`（否则 APK/安装包不会内嵌自托管前端）。
- `apps/readest-app/.env.server`：`NEXT_PUBLIC_SELFHOSTED=1` 是自托管逻辑的总开关。
- **禁用官方更新链路**（三处 SELFHOSTED 门控，合并后必须确认还在）：
  - `src/helpers/updater.ts` → `checkForAppUpdates` / `checkAppReleaseNotes` 早退。
  - `src/services/nativeAppService.ts` → `hasUpdater = !SELFHOSTED && ...`。
  - `src/components/AboutWindow.tsx` → `{!SELFHOSTED && ...}` 包裹检查更新按钮。
- 自托管专属功能：随机选书（random pick）、书架/分组置顶（pin，`Book.pinnedAt` + `settings.libraryPinnedGroups`）、服务端地址运行时输入。
- `readest-sync-server/` 是**独立的 Go 同步服务端**（SQLite/Postgres + 本地磁盘/MinIO），与上游 `docker/`（Supabase 方案）无关。上游的 `docker/volumes/db/migrations/*.sql` 不影响它。

## 陷阱

### 环境（WorkBuddy 会话内跑构建必读）

- **`NODE_OPTIONS` 会毒死构建**：会话环境里注入了
  `NODE_OPTIONS=--require=".../WorkBuddy/.../shim/node-language-shim.cjs"`。
  它会被 Next.js 的构建 worker 继承，导致 `next build` 停在
  `✓ Running next.config.mjs` 之后**完全卡死**（CPU 几乎不涨、无任何输出、
  无限等待）。跑任何 Node 构建前必须先 `unset NODE_OPTIONS`。
  需要限制堆时用 `export NODE_OPTIONS="--max-old-space-size=4096"`（只放堆参数）。
- **`rm` 是坏的**：环境里 `rm` 被替换成 `safe-bin/rm` shim，会报
  `cd: null directory` / `safe_delete_main: command not found`（exit 127）。
  删文件请用 Python（`python.exe -c "import os; os.remove(...)"`）或 PowerShell。
  同理 `wmic.exe` 被安全策略禁用。
- **内存**：这台机器 24 GB 物理内存经常只剩 2~3 GB 可用、可提交内存只剩几百 MB。
  内存耗尽时的报错是 `RangeError: Array buffer allocation failed`（Node）或
  `memory allocation of N bytes failed`（Rust/tauri CLI）。
  这不是代码问题——先让用户关掉一些程序（浏览器/Steam/KOOK 等）再构建。
- husky 的 `pre-commit`（`pnpm exec lint-staged` → biome）在内存不足时会直接把
  node 进程崩掉，表现为 `husky - pre-commit script failed (code 3)`，提交被中止。

### 仓库

- `apps/readest-app/src-tauri/gen/` 被 `apps/readest-app/.gitignore` 忽略，但其中 75 个文件是**已跟踪**的。`git add <目录>` 会被拒，必须逐个文件路径加，或用 `git add -u`。
- 上游同时跟踪 `gen/android/**`（31 个文件，包名 `com.bilingify.readest`），而本分支改成了 `com/ywz626/readest/sh`。合并 `gen/android/app/build.gradle.kts` 时要确认 namespace/applicationId 仍是自托管值。
- `zh-CN/translation.json` 里 `"Filters"` 键重复（自托管随机选书加了 `筛选条件`，基线的 `筛选` 仍在），JSON 后者生效——属既有小问题。
- `packages/tauri`、`tauri-plugin-turso` 子模块内常有「autogenerated 权限/schema 文件」改动，是构建产物噪音，不用管。
- rustup 镜像（tuna）缺 `rust-std-*-android` 组件会 404，但**工具链里已有可用的 android std 库**，`rustc --target aarch64-linux-android` 能正常编译；不用强行 `rustup target add`。

## 构建（Windows / Android）

在 `apps/readest-app/` 下执行（脚本已内置自托管 env）：

```bash
pnpm build-server-win-x64-64bit   # Windows x64 NSIS 安装包
pnpm build-server-android          # Android APK（脚本尾部含 adb install，无设备时会非零退出，构建本身已完成）
```

产物：`apps/readest-app/src-tauri/target/<target>/release/bundle/{nsis,msi}/`
Android APK：`apps/readest-app/src-tauri/gen/android/app/build/outputs/apk/universal/release/`
